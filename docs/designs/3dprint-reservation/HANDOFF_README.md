# Handoff: 3Dプリントの依頼・予約（3D print request & reservation）

ScienceHUB（松山南高校 自然科学部）内のアプリ `/apps/3dprint-reservation/` として動く、
3Dプリンターの **依頼（印刷依頼）** と **予約（時間確保）** を行う1画面のWebアプリ。

---

## Overview

- **誰が**: 自然科学部の部員・生徒（初めて使う1年生を含む）。PCの教室端末とスマートフォンの両方。
- **何を**: 4週分のカレンダーから日付を選び、6:00〜20:00 のタイムラインで時間を指定して申請する。申請はカレンダーの上に重なるポップで完了する。
- **解決すること**: 「どの日に誰（担当者）がいるか」「どこが空いているか」をカレンダー上で一覧でき、空き時間の重複申請を仕組みで防ぐ。
- **制約（業務ルール）**
  - 担当者（金田・田村・藤原）のシフトは **平日のみ**。土日は受付なし。
  - **予約**は 6:00〜20:00 の範囲で時間指定（当日も可）。
  - **依頼**は時間指定なし。そのプリンターの **16:30〜20:00 を丸ごと占有**する。受付は **前日まで**（当日の依頼は不可）。
  - 同じ機種・同じ時間帯が埋まっている場合は追加申請不可（重複ガード）。

## About the Design Files

このバンドルの HTML / CSS / JSX は **HTML で作られたデザインリファレンス（高忠実度プロトタイプ）** です。
本番コードとしてそのまま貼るものではなく、**ターゲットのコードベース（React / Next.js / Vue / SwiftUI など）の既存パターン・ライブラリで再現する** ことが目的です。環境がまだない場合は、React + TypeScript（Vite か Next.js）を推奨します。

参考実装は React 18（UMD）+ インライン Babel で書かれているため、`<script type="text/babel">` をそのまま本番に持ち込まないこと。各 `js/*.jsx` は **1コンポーネントファイルとしてそのまま移植できる粒度** で分割してあります（`Chrome / Calendar / Timetable / Popover / Sheets / App`）。`js/core.js` はフレームワーク非依存のドメインロジックなので、そのまま（もしくは TypeScript の `domain.ts` に）移植できます。

## Interactions & Behavior

### 日付選択
- 日セルクリック → `selected` 更新、選択範囲クリア、開いているポップを閉じる。4週の起点がその日を含む週に移動（＝選択日は必ず第1週に現れる）。
- `‹` `›` は選択日を ±28日 して 4週送り。「今日」は今日を選択。
- 土日・シフトなしの日: タイムラインは全てストライプ＆操作不可。注意書き（`warn`）に「この日は担当者のシフトがありません。予約・依頼とも、担当者のいる平日のみ受け付けています。」＋「次の空き日へ」ボタン（次に空きのある平日へジャンプ）。ポップも開かない（トースト `この日は担当者がいません`）。
- 過去日: 申請不可（トースト `過ぎた日には申請できません`）。

### 時間選択 → ポップ自動展開
- レーン上で `pointerdown` → 起点スロット（占有済みなら無反応）。`pointermove` で範囲を伸縮（`clampRange` が占有スロットで停止、6:00〜20:00 にクランプ）。`pointerup` で `selection = {machine, start, end}` を確定し、**同時にポップを開く**（`kind` は `reserve` 初期値）。
- クリックのみ（移動なし）でも 1枠（30分）選択として扱い、ポップが開く。
- ポップ内のホイール操作は `selection` に同期し、タイムラインのハイライトも動く。
- 選択バーの長さプリセット（30分/1時間/1時間30分/2時間）は開始時刻を固定して末尾を伸ばす。収まらない長さは disabled。

### 申請の種類切替
- `依頼` を選ぶと時間UIが固定枠に変わり、`selection` を 16:30〜20:00 の帯へ差し替え（タイムライン上で帯全体がハイライト）。
- `予約` に戻すと元の時間選択へ戻る。

### 送信
- `hasOverlap()` で同一機種・同一時間帯の重複を再チェック。重複時はトースト `同じ時間帯にすでに申請があります`。
- 成功時: 申請を配列へ追加（`status:'pending'`, `mine:true`）、ポップを閉じ、選択をクリア、トースト（`依頼を受け付けました（申請中）` / `予約を申請しました（申請中）`）。
- **依頼の占有範囲**: データには `start/end` = 16:30/20:00 を保存する。表示・重複判定は `spanOf()` を通すので、依頼は常に受付帯全体として扱われる。
- 申請者の `HR / 番号 / 名前` は送信成功時に localStorage へ保存（次回自動復元）。

### マイクロアニメーション（デザインシステム準拠）
- 日付変更時: ヘッダー `.35s` 下からフェード → タイムテーブル `.4s`（+30ms）→ レーン `.4s`（+50/100ms）→ 一覧 `.4s`（+80ms）、`cubic-bezier(.2,.8,.2,1)`。
- ポップ: `popIn .26s`、スクリム `.18s` フェード。
- 選択バー出現時: 左端に 3px `#f38020` の縦線が上から伸びる（`scaleY` .4s）。
- ドロワー: デスクトップ `translateX` .28s／モバイル `translateY` .28s。
- `prefers-reduced-motion: reduce` で全アニメーション・トランジションを停止。

### レスポンシブ
- **1180px以下**: 右カラム 400 → 376px。
- **1040px以下**: 1カラム縦積み（カレンダー → 日パネル）。タイムテーブル最大高 360px。
- **720px以下**: 余白 16px、ヘッダーはタイトル補助テキストと「申請一覧」ラベルを省略。日セル min-height 70px、予約行は時刻を隠して1行省略。ポップは**画面下からのボトムシート**（`position:fixed`、`border-radius:16px 16px 0 0`、最大高94vh、フッターのボタンは等幅）。ドロワーもボトムシート化。トーストは左右いっぱい。
- **520px以下**: 申請者の入力3列を `96px 58px 1fr` に詰める。
- **420px以下**: 月見出し 15px、日セル min-height 66px、`‹ ›` を 26px に縮小。
- タップターゲットは 44px 以上を確保（日セル・ボタン・ホイール項目36px＋スナップ）。

## State Management

```ts
type Kind = 'request' | 'reserve';
type Status = 'pending' | 'approved' | 'rejected' | 'done';

type Who = { name: string; hr: string; num: string };   // hr: '101'〜'309'

type Application = {
  id: string;
  date: string;          // 'YYYY-MM-DD'
  machine: 'ke' | 'cc';
  kind: Kind;
  start: number;         // 分（6:00 = 360）。依頼は常に 990
  end: number;           // 分。依頼は常に 1200
  title: string;         // 用途 / 作品名
  file: string;          // 印刷データのファイル名
  fileSize?: number;     // bytes
  note: string;
  who: Who;
  status: Status;
  mine?: boolean;
  createdAt?: string;
};
```

**App の状態**
| 変数 | 型 | 役割 |
|---|---|---|
| `apps` | `Application[]` | 全申請。変更のたび localStorage `sh3d.reservations.v3` に保存 |
| `selected` | `string` | 選択日。`sh3d.prefs.v3` に保存しリロードで復元 |
| `selection` | `{machine,start,end} \| null` | タイムラインのハイライト範囲 |
| `form` | `{open, draft}` | ポップの開閉と初期値（`draft = {date,machine,start,end,kind}`） |
| `profile` | `{hr,num,name}` | 前回の申請者。`sh3d.profile.v2` |
| `detail` / `mineOpen` / `toast` | — | ドロワー・トースト |

**派生値（メモ化推奨）**: `computeDay(apps, selected)` → `{shift, staff, list, machines:{ke,cc}, full}`。`machines[id].blocked` は 28要素の配列（占有中の申請 or `null`）。`free` は空き枠数。`findNextOpenDate(apps, selected)` は次の空き日。

**日付・時間のユーティリティ（`js/core.js` / 移植そのまま）**
- `ymd` / `parseYmd` / `addDays` / `startOfDay` / `isWeekday` / `weekStart`（日曜始まり）
- `slotStart(i) = 360 + i*30`、`slotIndex(min) = (min-360)/30`、`minsLabel`、`durationLabel`
- `inShiftSlot(i)` = 16:30〜20:00 の枠か
- `spanOf(app)` = 依頼なら受付帯全体、予約なら実時間の占有範囲
- `clampRange(anchor, idx, blocked)` = 占有スロットの手前で止めた連続範囲
- `requestAllowed(date)` = `date < today`（前日まで）
- `hasOverlap(apps, cand)`、`HR_LIST`（101〜309）、`hrLabel`、`whoLabel`

**バックエンドに移すとき**: `apps` の CRUD を API に置き換える（`GET /applications?from&to`, `POST /applications`, `PATCH /:id/status`, `DELETE /:id`）。重複判定 `hasOverlap` は**サーバー側でも必ず実行**（クライアントは楽観表示のみ）。ファイルは署名付きURLへ直接アップロードし、`Application.file` には表示名、`fileKey` に実体キーを持たせるのが望ましい。担当者シフト（`hasShift` / `staffFor`）はダミー実装なので、実運用ではシフトAPIに置き換える。`mine` は認証ユーザーID比較に置き換える。
